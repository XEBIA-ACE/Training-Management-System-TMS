# US-003 create trainer profile: unresolved gaps and provisional choices

Status: open. Needs product and security confirmation.

`specs/US-003/plan.md` lists `artifact-SVC-005-api_spec`, `artifact-SVC-005-c3`/`c4` and
`service:SVC-012` as unresolved. The implementation of `POST /api/v1/trainers` (`com.tms.trainer`)
makes the provisional choices below and marks them with `GAP(...)` comments in code. Treat none of
them as an approved contract.

| Ref | Gap | Provisional choice | Where |
| --- | --- | --- | --- |
| Contract | TrainerCreateRequest schema (api_spec unresolved) | Fields: `trainerType`, `employeeId`, `name`, `email`, `location`, `msaNdaStatus`, `msaNdaReference`, `weekendAvailable`, `certificationIds`. Rates and internal incentive applicability appear in the story behaviour but have no defined fields, so they are **not** accepted yet. Length limits follow the `trainer` table. | `TrainerCreateRequest`, `TrainerCreateCommand` |
| Contract | Response / path | 201 + `Location: /api/v1/trainers/{id}`, body = `TrainerResponse` (US-002 shape plus `trainerType, location, timeZone, msaNdaStatus, msaNdaReference`). US-002 reads are also mapped under `/api/v1/trainers`, so `GET /api/v1/trainers?status=ACTIVE` exists (FR-US-003-005). `/api/trainers` is unchanged. | `TrainerController` |
| FR-US-003-001/002 | Validation order and shape | 401/403 first, then **all** field errors in one 400 `VALIDATION_FAILED` (`details[]` = `{field, message}`, sorted by field). `trainerType` must be exactly `INTERNAL`/`EXTERNAL`. A malformed JSON type (e.g. a non-UUID certification id) gives 400 on that field path. | `TrainerCreateValidator`, `TrainerApiExceptionHandler` |
| FR-US-003-002 | `msaNdaStatus` enum values are not defined anywhere | `PENDING`, `SIGNED`, `EXPIRED` (optional). Also accepted for INTERNAL trainers because the spec gives no rule. | `MsaNdaStatus` |
| FR-US-003-003 | Error codes; uniqueness semantics | 409 `TRAINER_DUPLICATE_EMPLOYEE_ID` / `TRAINER_DUPLICATE_EMAIL`, with `details[0].field`. employeeId is checked against all trainers for INTERNAL requests (EXTERNAL requests do not check it). Email is checked case-insensitively against all trainers. Both checks include inactive trainers. employeeId is checked first. DB unique indexes `uq_trainer_email_lower` and `uq_trainer_internal_employee_id` close the race between concurrent creates. **`V7` fails if existing rows already have duplicate emails (case-insensitive) or duplicate INTERNAL employeeIds.** | `TrainerDomainService`, `V7__trainer_create_attributes.sql` |
| FR-US-003-004 | Location master data and time zone mapping rules do not exist | Mapping is configuration: `tms.trainer.management.location-time-zones` (`TMS_TRAINER_LOCATION_TIME_ZONES`), entries `<location>=<IANA zone id>`, matched case-insensitively on the trimmed free-text location. **The default is empty, so no time zone is derived until rules are configured.** An unmapped location creates the trainer with `timeZone = null` (the story leaves this open). Malformed, unknown-zone or conflicting rules fail at startup. | `LocationTimeZoneRules`, `TrainerManagementProperties` |
| FR-US-003-005 | Status vocabulary | `ACTIVE` (same opaque string used by the US-002 filter). | `Trainer.STATUS_ACTIVE` |
| FR-US-003-006 | Audit field whitelist | One `CREATE` entry (`resource_type = Trainer`, `resource_id` = new id, actor, `occurred_at`). Details: `module=trainer, recordId, trainerType, employeeId, name, email, location, timeZone, status`. It never includes `msaNdaReference` (the document link) or certification ids, and the API takes no document contents. The entry is written in the **same transaction** as the trainer, so the trainer and its audit entry are both persisted or both rolled back. Audit details now contain personal data (name/email) because the story requires it, unlike US-002 search entries. | `TrainerAppService.createdDetails`, `AuditLogClient.appendInCurrentTransaction` |
| FR-US-003-007 | TRAINER.MANAGE permission (SVC-012 absent; `RbacPermissionEvaluator` fails closed) | Role-based, configurable `tms.trainer.management.roles` (`TMS_TRAINER_MANAGE_ROLES`, default `SUPER_ADMIN`). A 403 writes an `UNAUTHORIZED_ACCESS` entry (reason `MISSING_TRAINER_MANAGE_PERMISSION`), toggled by `tms.trainer.management.audit.unauthorized-access-enabled`. 401s are now logged as WARN security events by `SecurityErrorHandler` (method, path, code, no credentials). They are not audited because there is no actor. | `TrainerAppService`, `SecurityErrorHandler` |
