# Tasks: US-004

- [ ] T001 FR-US-004-001 (US-004-ac-1): The system must expose an API endpoint that maps to the trainer-app-api operation changeTrainerStatus(trainerId, newStatus) such that, when invoked by an authorized caller, AppTrainerService validates the caller's permission via the Authorization and RBAC Component before performing any update, and upon successful authorization updates only the Trainer entity's status field in the Trainer and Allocation Repository without modifying or deleting any other profile attributes.
- [ ] T002 FR-US-004-002 (US-004-ac-1): If the caller invoking changeTrainerStatus(trainerId, newStatus) is not authorized according to the Authorization and RBAC Component, AppTrainerService must not update the Trainer entity's status field and must return a failure response indicating lack of permission (specific error shape and code are not defined in the story and must be treated as an open design detail).
- [ ] T003 FR-US-004-003 (US-004-ac-2): When changeTrainerStatus sets a trainer's status to an inactive value, the Domain Services Layer and AppTrainerService must ensure that subsequent calls to searchTrainers(criteria) exclude that inactive trainer from allocation-eligible result sets that feed POST /api/workshops/{id}/allocate-trainer.
- [ ] T004 FR-US-004-004 (US-004-ac-2): When searchTrainers(criteria) is invoked with a dedicated includeInactive filter, the Domain Services Layer and AppTrainerService must allow inactive trainers to appear in search results for viewing purposes but must ensure that such inactive trainers are not treated as allocation-eligible by POST /api/workshops/{id}/allocate-trainer.
- [ ] T005 FR-US-004-005 (US-004-ac-3): When AppTrainerService processes allocateTrainerToWorkshop(workshopId, trainerId, role), it must consult the Trainer and Allocation Repository and Domain Services Layer to determine the target trainer's current status before creating any WorkshopAllocation record.
- [ ] T006 FR-US-004-006 (US-004-ac-3): If allocateTrainerToWorkshop(workshopId, trainerId, role) determines that the target trainer has an inactive status, AppTrainerService must fail the operation without creating a WorkshopAllocation record for that workshop-trainer-role combination.
- [ ] T007 FR-US-004-007 (US-004-ac-3): When allocateTrainerToWorkshop(workshopId, trainerId, role) fails due to an inactive trainer status, the API and Controller Layer must return a clear, localized error message indicating that inactive trainers cannot be allocated (the exact error code and localization strategy are not defined in the story and remain an open design detail).
- [ ] T008 FR-US-004-008 (US-004-ac-4): When changeTrainerStatus transitions a trainer from inactive back to active, AppTrainerService, together with TrainerRepository and CatalogRepository, must ensure that subsequent calls to searchTrainers(criteria) can once again return that trainer in their results, provided the trainer meets all other eligibility conditions in force at query time, such as required certifications and availability, using getTrainerConflicts and certification lookups as needed.
- [ ] T009 FR-US-004-009 (US-004-ac-4): After a trainer is transitioned from inactive to active via changeTrainerStatus, any allocation eligibility checks (including those used by allocateTrainerToWorkshop and POST /api/workshops/{id}/allocate-trainer) must include the trainer as eligible only if they satisfy current non-status eligibility rules (e.g., certifications and conflict checks via getTrainerConflicts), and must exclude them if those other rules are not satisfied.
- [ ] T010 FR-US-004-010 (US-004-ac-5): For every successful trainer status change executed via changeTrainerStatus, the Domain Services Layer and Audit Log Repository must append an immutable audit event that records at least the trainer identifier, previous status, new status, acting user, and timestamp.
- [ ] T011 FR-US-004-011 (US-004-ac-5): Audit events written for trainer status changes must be queryable via GET /api/admin/audit-logs, supporting filters that can locate trainer status change events based on at least the recorded fields (trainer identifier, previous status, new status, acting user, timestamp), noting that the exact filter parameter shapes and combinations are not specified in the story and remain an open design detail).
- [ ] T012 Verify US-004-ac-1: When an authorized caller invokes an API endpoint that maps to the trainer-app-api operation changeTrainerStatus(trainerId, newStatus), the AppTrainerService must validate the caller's permission via the Authorization and RBAC Component and update the Trainer entity's status field in the Trainer and Allocation Repository without modifying or deleting any other profile attributes.
- [ ] T013 Verify US-004-ac-2: When a trainer's status is set to an inactive value through changeTrainerStatus, the Domain Services Layer and AppTrainerService must ensure that subsequent calls to searchTrainers(criteria) exclude inactive trainers from general allocation-eligible result sets that are used by POST /api/workshops/{id}/allocate-trainer, unless a dedicated includeInactive filter explicitly allows viewing but not allocation.
- [ ] T014 Verify US-004-ac-3: When AppTrainerService processes allocateTrainerToWorkshop(workshopId, trainerId, role), it must consult the Trainer and Allocation Repository and Domain Services Layer so that if the target trainer has an inactive status the operation fails without creating a WorkshopAllocation record, and the API and Controller Layer returns a clear, localized error message indicating that inactive trainers cannot be allocated.
- [ ] T015 Verify US-004-ac-4: When changeTrainerStatus transitions a trainer from inactive back to active, AppTrainerService together with TrainerRepository and CatalogRepository must ensure that subsequent searchTrainers(criteria) and allocation eligibility checks once again include the trainer only if they meet other eligibility conditions such as required certifications and availability, using getTrainerConflicts and certification lookups as needed.
- [ ] T016 Verify US-004-ac-5: For every successful trainer status change executed via changeTrainerStatus, the Domain Services Layer and Audit Log Repository must append an immutable audit event that records the trainer identifier, previous status, new status, acting user, and timestamp, and this event must be queryable via GET /api/admin/audit-logs with appropriate filters.
