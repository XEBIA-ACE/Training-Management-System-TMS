# Tasks: US-003

- [ ] T001 FR-US-003-001 (US-003-ac-1): The POST /trainers endpoint MUST accept a TrainerCreateRequest with trainerType INTERNAL only if the request payload includes a non-empty employeeId, a syntactically well-formed email address, and all other required fields defined in the schema, at minimum including name and location; if any of these required fields are missing or malformed, the API MUST respond with HTTP 400 and an ErrorResponse containing field-level ValidationError entries that identify each invalid or missing field.
- [ ] T002 FR-US-003-002 (US-003-ac-2): For TrainerCreateRequest payloads with trainerType EXTERNAL, the POST /trainers endpoint MUST require that email, location, and name are present and syntactically well-formed, and MUST validate that any optional fields such as msaNdaStatus conform to their defined enum constraints; when any such validation fails, the API MUST respond with HTTP 400 and an ErrorResponse containing appropriate ValidationError entries, and MUST NOT persist a new trainer record.
- [ ] T003 FR-US-003-003 (US-003-ac-3): Before creating a trainer, the Trainer and Certification Repository layer MUST check for an existing trainer with the same employeeId when trainerType is INTERNAL, and for an existing trainer with the same email for both INTERNAL and EXTERNAL trainerTypes, considering all trainers including those marked inactive; if a duplicate employeeId or email is found, the controller MUST respond with HTTP 409 Conflict and an ErrorResponse whose errorCode explicitly indicates whether the conflict is due to duplicate employeeId or email, and MUST NOT persist a new trainer record.
- [ ] T004 FR-US-003-004 (US-003-ac-4): When a TrainerCreateRequest contains a location value that can be mapped to a known location or time zone rule, the Trainer and Certification Application Service MUST derive a specific timeZone value from that location, persist the derived timeZone on the trainer record, and ensure that the TrainerResponse for the successful POST /trainers call includes the populated timeZone field; if the mapping rules are ambiguous or incomplete, this requirement does not specify the behavior and such ambiguity MUST be treated as a separate design decision outside this story.
- [ ] T005 FR-US-003-005 (US-003-ac-5): On successful creation of a trainer via POST /trainers (i.e., all validations pass and no duplicates are detected), the Trainer and Certification Application Service MUST default the trainer’s status field to ACTIVE in persistent storage, MUST ensure that subsequent GET /trainers queries that filter by status ACTIVE include the newly created trainer, and MUST return the created trainer as a TrainerResponse suitable for use in downstream allocation and search flows.
- [ ] T006 FR-US-003-006 (US-003-ac-6): For every POST /trainers request that results in a successfully created trainer profile, the Trainer and Certification Application Service MUST create an immutable AuditEntry via the Audit and Logging Component with module set to "trainer", recordId set to the new trainerId, actor information derived from the authenticated user context, a timestamp of creation, and non-sensitive field values including at least name, email, employeeId, trainerType, and location, and MUST explicitly exclude any document file contents or other sensitive payload fields from the AuditEntry.
- [ ] T007 FR-US-003-007 (US-003-ac-7): The POST /trainers endpoint MUST be protected by authentication and authorization such that any request without valid authentication, or with insufficient permissions relative to the required TRAINER.MANAGE-style privilege enforced by the RBAC and Authorization Component, is rejected with HTTP 401 (unauthenticated) or HTTP 403 (forbidden); in these failure cases the system MUST NOT create or modify any trainer records and MUST still log the denied access via the configured security events and audit mechanisms consistent with the shared ErrorResponse and AuditEntry models.
- [ ] T008 Verify US-003-ac-1: When the frontend submits POST /trainers with trainerType INTERNAL, the TrainerCreateRequest validation must enforce that employeeId is present, email is well formed, and all other required fields in the schema name, location are provided; on any missing or malformed field the API must return HTTP 400 with an ErrorResponse that includes field level ValidationError entries highlighting the invalid fields.
- [ ] T009 Verify US-003-ac-2: When the frontend submits POST /trainers with trainerType EXTERNAL, the TrainerCreateRequest validation must enforce that email and location and name are present and well formed and that any optional fields such as msaNdaStatus follow their enum constraints; on validation failure the API must return HTTP 400 with appropriate ValidationError entries and must not create a trainer record.
- [ ] T010 Verify US-003-ac-3: When POST /trainers is called with an employeeId already present on any existing trainer for INTERNAL trainers or an email already present on any existing trainer for either INTERNAL or EXTERNAL trainers, including trainers that are currently inactive, the Trainer and Certification Repository lookup must detect the duplicate and the controller must return HTTP 409 Conflict with an ErrorResponse whose errorCode clearly indicates a duplicate employeeId or email and no new trainer record is persisted.
- [ ] T011 Verify US-003-ac-4: When POST /trainers is called with a valid location string that maps to a known location or time zone rule, the Trainer and Certification Application Service must derive a timeZone value based on that location and persist it to the trainer record so that TrainerResponse includes the populated timeZone field on success.
- [ ] T012 Verify US-003-ac-5: When a trainer is successfully created via POST /trainers the Trainer and Certification Application Service must default the trainer status field to ACTIVE in persistence and ensure that the new trainer appears in subsequent GET /trainers queries that filter by status ACTIVE and can be returned as a TrainerResponse used by downstream allocation and search flows.
- [ ] T013 Verify US-003-ac-6: On every successful invocation of POST /trainers that results in a new trainer profile, the Trainer and Certification Application Service must create an immutable AuditEntry via the Audit and Logging Component with module set to trainer, recordId set to the new trainerId, actor information from the authenticated user, timestamp of creation, and non sensitive field values such as name, email, employeeId, trainerType and location while excluding any document file contents.
- [ ] T014 Verify US-003-ac-7: If POST /trainers is attempted without authentication or with insufficient TRAINER.MANAGE style permissions as enforced by the RBAC and Authorization Component, the API must reject the request with 401 or 403 and must not create or modify any trainer records, while still logging denied access through the security events and audit mechanisms as described in the shared ErrorResponse and AuditEntry models.
