# Tasks: US-002

- [ ] T001 FR-US-002-001 (maps US-002-ac-1): The TrainerController and TrainerAppService SHALL implement GET /trainers such that, when any combination of the query parameters status, certificationId, availabilityState, locationId, weekendAvailable, and search is supplied, the PagedTrainerList.items collection includes only Trainer entities that satisfy every provided parameter’s filter condition, and MUST NOT include any Trainer entity that violates at least one of the provided filters. The exact semantics of each filter value (e.g., allowed status values, availabilityState values) are not defined in this story and MUST be treated as externally defined or clarified elsewhere.
- [ ] T002 FR-US-002-002 (maps US-002-ac-2): The TrainerRepository.Search implementation used by GET /trainers SHALL, when the search query parameter is present, evaluate the search term as a free-text predicate over trainer name, email, and employeeId fields and SHALL logically combine this predicate with all other active filters (status, certificationId, availabilityState, locationId, weekendAvailable) so that returned trainers satisfy both the text predicate and all other filters. The story does not specify the matching algorithm (e.g., contains vs. prefix vs. fuzzy), which remains ambiguous and must not be assumed from this requirement alone.
- [ ] T003 FR-US-002-003 (maps US-002-ac-3): For GET /trainers requests under expected production-scale volumes of Trainer records, the combined behavior of TrainerAppService, TrainerRepository, and any CacheAdapter usage for trainer lookups SHALL keep the end-to-end HTTP response time within the agreed performance SLO for this operation and SHALL avoid HTTP timeouts, with compliance observable via LoggingMonitoring metrics for GET /trainers. The concrete SLO values and volume thresholds are not specified in this story and are assumed to be defined externally.
- [ ] T004 FR-US-002-004 (maps US-002-ac-4): When a caller with valid bearerAuth and appropriate RBAC permissions invokes GET /trainers/{trainerId} for a trainerId that appears in a previously obtained PagedTrainerList, the endpoint SHALL return the Trainer details corresponding to that trainerId and SHALL ensure that no trainer data for which the caller lacks permission is included in the response. If RBAC or other authorization rules deny access to the requested trainer, the implementation SHALL prevent data leakage as per configured authorization behavior (e.g., by not returning restricted trainers); the precise error semantics in this denial case are not specified in this story.
- [ ] T005 FR-US-002-005 (maps US-002-ac-5): When an allocation workflow is initiated from an action on a trainer selected in the directory, the system SHALL enable downstream allocation APIs to be called using the trainer id and basic attributes already present in the Trainer aggregate as returned by PagedTrainerList or Trainer (GET /trainers/{trainerId}), and SHALL NOT require additional service round trips solely to re-resolve core trainer identity data (such as the trainer’s unique id and other basic identifying attributes). The exact set of attributes considered “basic” or “core identity data” is not defined in this story and remains an explicit ambiguity.
- [ ] T006 FR-US-002-006 (maps US-002-ac-6): For each GET /trainers request that meets internal auditing policy criteria for search and filter operations, TrainerAppService SHALL invoke AuditLogClient.AppendAuditEntry or a functionally equivalent mechanism so that an audit record is persisted containing at least: (a) the actor identity, (b) a timestamp, and (c) a high-level summary of which filter fields were used and whether a free-text search term was present. The implementation SHALL NOT persist the raw free-text search value itself in the audit log. The story does not define how “satisfies internal auditing policy” is determined, so the triggering rules for auditing are treated as externally defined.
- [ ] T007 FR-US-002-007 (maps US-002-ac-7): All operations for trainer search and profile retrieval exposed via GET /trainers and GET /trainers/{trainerId} SHALL enforce security using bearerAuth and AuthContextProvider-based authorization such that callers lacking appropriate trainer directory permissions receive an HTTP 403 response, and, where required by policy, an UnauthorizedAccessEntry (or equivalent) is written. The specific mapping between RBAC roles/permissions and access decisions is not defined in this story and must be obtained from external security configuration or policy.
- [ ] T008 Verify US-002-ac-1: When the frontend trainer directory invokes GET /trainers with combinations of query parameters status, certificationId, availabilityState, locationId, weekendAvailable, and search, the TrainerController and TrainerAppService must ensure that only Trainer entities matching all provided criteria are returned in the PagedTrainerList items collection, with no records that violate any of the filters.
- [ ] T009 Verify US-002-ac-2: When the search query parameter on GET /trainers contains a free text term representing trainer name, email, or employeeId, the TrainerRepository.Search implementation must match on those fields and combine the text predicate with all other active filters so that the effective result set respects both the search term and filter parameters together.
- [ ] T010 Verify US-002-ac-3: Under expected production-scale volumes of Trainer records, the TrainerAppService, TrainerRepository, and any use of CacheAdapter for trainer lookups must keep the end to end GET /trainers response time within the agreed performance SLO and avoid HTTP timeouts, as observed via LoggingMonitoring metrics for this operation.
- [ ] T011 Verify US-002-ac-4: When an authorized user selects an individual trainer from the filtered results and navigates to that profile, the GET /trainers/{trainerId} endpoint must return the corresponding Trainer details for the id present in the PagedTrainerList without leaking trainers the caller is not permitted to view, enforcing bearerAuth and RBAC checks as configured.
- [ ] T012 Verify US-002-ac-5: When an allocation workflow initiates from an action on a trainer in the directory, the system must be able to use the trainer id and basic attributes from the Trainer aggregate (as returned in PagedTrainerList or Trainer) to call downstream allocation APIs, without requiring additional round trips to resolve core trainer identity data.
- [ ] T013 Verify US-002-ac-6: For each GET /trainers request that satisfies internal auditing policy for search and filter operations, TrainerAppService must invoke AuditLogClient.AppendAuditEntry or equivalent so that an audit record is written identifying the actor, timestamp, and a high level summary of the applied criteria (such as which filter fields were used and whether free text was present), without persisting the raw free text content itself.
- [ ] T014 Verify US-002-ac-7: All trainer search and profile retrieval operations exposed via GET /trainers and GET /trainers/{trainerId} must enforce security through bearerAuth and AuthContextProvider so that users lacking appropriate trainer directory permissions receive a 403 response and an UnauthorizedAccessEntry is written if required by policy.
